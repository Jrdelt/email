# Roadmap

Each task lists acceptance criteria. Check the box when all are met and CI passes.

- [x] **T0 Scaffold**: extension builds for Chrome, Edge, Firefox; ml tests pass.
- [x] **T0b Detection actions**: banner (shadow DOM) with "I trust this email" (persisted locally as a one-way SHA-256 fingerprint across refreshes and reversible via an inline **Undo** pill or popup Clear), auth-guarded "Always trust sender" (local allowlist enabled when sender is extracted, manageable in popup), and "Not phishing" (local false-positive report, no email content stored). Links and forms in flagged emails are locked until unlocked.
- [x] **T0c Sender and domain checks**: banner shows sender, address validity, relay (`via`), authentication, and domain details; local warnings (invalid address, brand name from the wrong domain including compact/camelCase forms, lookalike/punycode domains, address in display name, conflicting relay/unverified auth); online lookups of domains only (RDAP age/registrar, MX/SPF/DMARC, NXDOMAIN), cached 24 h. (A URIBL spam-report check was removed later: URIBL refuses queries from public resolvers, so it almost never answered.) Any sender/domain warning pauses links alongside content warnings (never blocks reading the email).
- [x] **T0d Defense-in-depth, click-time guard & UX hardening**: neo-brutalist banner/popup/icon styling; multi-message thread scanning (`extractAll`); auto-synced repo-root `chrome-mv3/` build; cross-frame iCloud Mail adapter (all frames on iCloud's app and message frames only, top frame elsewhere; stateless `sender.url`-verified relay); cloud-storage HTML lure & expanded urgency/brand detection; DOM-clobbering-safe `linkLock`/`attachmentLock`/`extract` (`formaction`, SVG `href`/`xlink:href`, `<a ping>`, `keydown` `Enter`/`Space`, instant mutation re-locking); always-on attachment blocking + local filename risk classification for untrusted emails; Shadow DOM `:host { all: initial !important }` mounted on `document.documentElement`; strict MV3 CSP; click-time destination inspector + `warning.html` interstitial & recovery guide + 400 ms scan race gate; paused-action toast, 2-step `danger` unlock, `From` vs `Links go to` comparison cue, and post-trust Undo pill.
- [x] **T1 Parity fixtures**: create `ml/tests/fixtures/parity.json` (>=20 cases: sender, body, links, expected features). Python and TS tests both load it and assert equal features.
- [ ] **T2 Data**: implement `phishml/data.py` `load_dataset()` returning a DataFrame with columns `sender, subject, body, links, label, date, source` (`data.COLUMNS`): `sender` is the bare From address, `subject` the decoded Subject, `body` the visible text (not HTML), and `links` the browser-resolved `<a>`/`<area>` hrefs with their shown text. Implement `data.scoring_input()` so that `ml/tests/test_scoring_input.py` passes (it reads `ml/tests/fixtures/scoring_input.json`, which the TypeScript suite checks against the real extension code), then remove its strict-xfail marker; the owner may instead decide to run the extension's own TypeScript extraction. Document sources in `ml/data/SOURCES.md`. Include a tiny synthetic sample under `ml/tests/fixtures/` so tests run offline.
- [ ] **T3 Baseline model**: `train.py` trains logistic regression on `FEATURE_NAMES`; `evaluate.py` does a time-based split and prints precision@0.1% FPR, PR-AUC, confusion matrix. Results table into `docs/results.md`. Precision@0.1% FPR is the operating point from `evaluate.precision_at_fpr` (largest recall within the budget, ties never split; needs at least 1000 test negatives): report recall, threshold, false-positive count and number of negatives next to it, plus precision re-weighted to a stated prevalence. The split follows the `evaluate.time_split` contract (one date cutoff, rows without a date dropped, test bodies that also occur in train removed, both classes on both sides). `train.py` and `evaluate.py` compute features only as `extract_features(*scoring_input(...))`. Remove the strict-xfail markers in `ml/tests/test_pipeline_stubs.py` when implementing.
- [ ] **T4 Better model**: small gradient-boosted trees (shallow, few trees) plus hashed text features; beat T3 on the same time split. Model JSON must stay under 200 KB.
- [ ] **T5 Model export**: `export_model.py` writes `extension/public/model.json` (weights or small tree ensemble, <200 KB) plus its SHA-256 in `model.sha256`, and records `feature_names` (in `ml/tests/fixtures/feature_names.json` order) plus `python_version`/`unidata_version` in the JSON. Test: the pure-Python reference evaluator `export_model.reference_score(model_json, features)` matches sklearn within 1e-6 on fixtures (`ml/tests/test_pipeline_stubs.py::test_exported_json_matches_sklearn`). The pipeline runs on the Python pinned in `ml/.python-version` (3.13, Unicode 15.1; a test enforces it), because feature extraction depends on the interpreter's Unicode tables. `features.py` parses hosts per WHATWG/UTS46 without the stdlib `idna` codec; known residual drift from the extension: about 60 Unicode-14 right-to-left/combining characters and CJK Extension I, which Node's URL parser handles with older tables, and characters added after Unicode 15.1.
- [ ] **T6 In-extension inference**: `src/model.ts` loads the bundled JSON (no network, no ML runtime), verifies the hash, scores in plain TS, and matches the Python reference on fixtures. Falls back to heuristics if loading fails, or if the model's `feature_names` differ from `FEATURE_NAMES`. Must meet the performance budget in AGENTS.md.
- [ ] **T7 Adapters**: implement and verify adapters in `src/adapters/` for Gmail, Outlook (`live`/`office`/`office365`/`outlook.cloud.microsoft`), Yahoo (`mail.yahoo.com`), Proton (`mail.proton.me`), and iCloud, each returning `{sender, body, links}`. All 5 provider adapters are implemented and unit-tested against synthetic DOM fixtures (`gmail`, `outlook`, `icloud`, `yahoo`, `proton`); live inbox verification & real sanitized E2E smoke fixtures remain open before checking off. Can be tracked per provider (T7a Gmail, T7b Outlook, T7c Yahoo, T7d Proton, T7e iCloud).
- [ ] **T8 Explainability**: top contributing features become the human-readable reasons in the banner and popup.
- [ ] **T9 Hardening**: evasion tests (homoglyphs, shorteners, HTML-only links); false-positive report and allowlist flow; update the threat model.
- [ ] **T9b Performance check**: measure scoring time and memory on a long email and a busy inbox; add a vitest benchmark asserting <10 ms.
- [ ] **T10 Release**: Playwright smoke test on Chromium and Firefox; `npm run zip:all`; store listings and the privacy policy.
